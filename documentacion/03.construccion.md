## 1. INTRODUCCIÓN Y ALCANCE

### 1.1 Propósito del Sistema

SGCEA es un sistema de información web diseñado para digitalizar y centralizar los procesos académicos y administrativos de instituciones educativas, eliminando por completo la dependencia de archivos físicos o herramientas ofimáticas descentralizadas. El sistema se fundamenta en los principios de **centralización absoluta**, **eficiencia operativa** y **acceso controlado por permisos individuales (ACL)**.

### 1.2 Objetivos del Sistema

| Objetivo | Descripción | Métrica de Éxito |
|----------|-------------|------------------|
| **Centralización** | Toda la información reside en una única base de datos relacional, sin exportaciones a Excel que fragmenten los datos. | 100% de datos en el sistema. |
| **Automatización** | Procesos como cálculo de promedios, generación de constancias y reportes se realizan automáticamente. | 90% de procesos automatizados. |
| **Accesibilidad** | Acceso desde cualquier dispositivo con navegador, con interfaz adaptable (Bootstrap 5). | Disponibilidad 99.5% en horario laboral. |
| **Seguridad Granular** | Cada usuario tiene permisos específicos (ACL), no roles genéricos. | 0 brechas de seguridad. |
| **Rendimiento** | Tiempos de respuesta < 1s para consultas simples, < 3s para reportes complejos. | Cumplimiento SLA. |

### 1.3 Alcance del Sistema

#### Incluye (In-Scope)

✅ Gestión de usuarios y permisos individuales (ACL)  
✅ Administración de materias, grados y secciones  
✅ Asignación de carga académica a docentes  
✅ Registro de calificaciones con planes de evaluación flexibles (ponderaciones)  
✅ Control de asistencia estudiantil  
✅ Solicitud y emisión de constancias académicas (mediante vista de impresión)  
✅ Generación de carnets institucionales (vista de impresión)  
✅ Reportes y boletines académicos (consultas optimizadas con JOIN)  
✅ Configuración institucional  
✅ Caché de dashboards para alto rendimiento  
✅ Rate limiting de login mediante base de datos  

#### No Incluye (Out-of-Scope)

❌ Gestión financiera o pagos de matrícula  
❌ Comunicación directa padre-representante (chat/mensajería)  
❌ Biblioteca virtual o recursos educativos digitales  
❌ Admisiones y proceso de inscripción inicial  
❌ Nómina de personal docente  
❌ Inventario de recursos físicos

### 2.2 Flujo de Petición HTTP

1. Petición HTTP → `public/index.php` (Front Controller).
2. `index.php` → `bootstrap/app.php` (carga configuración, sesión, autoloader).
3. Router (`core/Router.php`) analiza URL y método HTTP.
4. Router busca ruta en `config/routes.php`, donde cada ruta tiene asociado un **permiso** requerido.
5. Router verifica autenticación y, si existe permiso requerido, valida que el usuario lo tenga (usando `$_SESSION['usuario_permisos']`).
6. Si no autenticado → redirige a login. Si no tiene permiso → error 403.
7. Router instancia el Controlador (inyección de dependencias) y ejecuta el método.
8. Controlador llama a los Services correspondientes.
9. Services usan Repositories para acceder a datos (consultas optimizadas con JOIN).
10. Repositories retornan arrays asociativos.
11. Controlador renderiza Vista con datos.
12. Vista genera HTML (con DataTables, Toasts, etc.) y lo envía al cliente.

#### 2.3.1 Router con Verificación de Permisos (ACL Nativo)

```php
// core/Router.php
class Router {
    private array $rutas = [];

    public function get(string $ruta, array $controladorMetodo, ?string $permiso = null): void {
        $this->rutas['GET'][$ruta] = [
            'controlador' => $controladorMetodo[0],
            'metodo'      => $controladorMetodo[1],
            'permiso'     => $permiso
        ];
    }

    public function post(string $ruta, array $controladorMetodo, ?string $permiso = null): void {
        $this->rutas['POST'][$ruta] = [
            'controlador' => $controladorMetodo[0],
            'metodo'      => $controladorMetodo[1],
            'permiso'     => $permiso
        ];
    }

    public function resolver(string $url, string $metodoHttp): void {
        $ruta = $this->rutas[$metodoHttp][$url] ?? null;
        if (!$ruta) {
            $this->lanzar404();
            return;
        }

        // Verificar autenticación
        if (!isset($_SESSION['usuario_id'])) {
            header('Location: index.php?url=/');
            exit;
        }

        // Verificar permiso (ACL)
        if ($ruta['permiso'] && !$this->tienePermiso($ruta['permiso'])) {
            http_response_code(403);
            require __DIR__ . '/../app/Views/errors/403.php';
            exit;
        }

        // Instanciar controlador (con DI)
        $nombreControlador = "Src\\Controllers\\" . $ruta['controlador'];
        if (class_exists($nombreControlador)) {
            $controlador = $this->container->resolver($nombreControlador);
            if (method_exists($controlador, $ruta['metodo'])) {
                $controlador->{$ruta['metodo']}();
                return;
            }
        }
        $this->lanzar404();
    }

    private function tienePermiso(string $permiso): bool {
        return isset($_SESSION['usuario_permisos'][$permiso]) && $_SESSION['usuario_permisos'][$permiso] === true;
    }
}
```

#### 2.3.3 Database y Rate Limiting en BD

```php
// core/Database.php
class Database {
    private static ?Database $instance = null;
    private ?PDO $connection = null;

    private function __construct() {
        $this->connect();
    }

    public static function getInstance(): Database {
        if (self::$instance === null) {
            self::$instance = new self();
        }
        return self::$instance;
    }

    public function conectar(): PDO {
        return $this->connection;
    }

    private function connect(): void {
        $config = require __DIR__ . '/../config/database.php';
        $dsn = "mysql:host={$config['host']};dbname={$config['dbname']};charset=utf8mb4";
        $this->connection = new PDO($dsn, $config['username'], $config['password'], [
            PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
            PDO::ATTR_EMULATE_PREPARES => false,
        ]);
    }
}

// core/RateLimiter.php
class RateLimiter {
    private PDO $db;
    private int $maxAttempts = 5;
    private int $windowMinutes = 15;

    public function __construct(PDO $db) {
        $this->db = $db;
    }

    public function isLimited(string $ip): bool {
        $sql = "SELECT COUNT(*) FROM intentos_login WHERE ip_address = :ip AND fecha_intento > DATE_SUB(NOW(), INTERVAL :window MINUTE)";
        $stmt = $this->db->prepare($sql);
        $stmt->execute([':ip' => $ip, ':window' => $this->windowMinutes]);
        return $stmt->fetchColumn() >= $this->maxAttempts;
    }

    public function registerAttempt(string $ip): void {
        $sql = "INSERT INTO intentos_login (ip_address) VALUES (:ip)";
        $stmt = $this->db->prepare($sql);
        $stmt->execute([':ip' => $ip]);
    }

    public function resetAttempts(string $ip): void {
        $sql = "DELETE FROM intentos_login WHERE ip_address = :ip";
        $stmt = $this->db->prepare($sql);
        $stmt->execute([':ip' => $ip]);
    }
}
```

### 4.1 Algoritmo de Matrícula/Inscripción

**Objetivo:** Registrar un estudiante en una sección específica para un año lectivo, validando cupos y evitando duplicados.

**Pseudocódigo:**
```text
FUNCION InscribirEstudiante(id_estudiante, id_seccion, anio_lectivo):
    INICIAR Transaccion BD
    TRY:
        // 1. Validar existencia del estudiante
        estudiante = EstudianteRepository.buscar(id_estudiante)
        SI estudiante ES NULO:
            RETORNAR Error("Estudiante no existe")
        
        // 2. Validar cupo disponible
        seccion = SeccionRepository.obtenerConCupo(id_seccion)
        inscritos_actuales = InscripcionRepository.contarPorSeccionYAnio(id_seccion, anio_lectivo)
        SI inscritos_actuales >= seccion.cupo_maximo:
            RETORNAR Error("Cupo lleno para esta sección")
        
        // 3. Validar duplicidad (no doble matrícula mismo año)
        existente = InscripcionRepository.buscarActiva(id_estudiante, anio_lectivo)
        SI existente NO ES NULO:
            RETORNAR Error("Estudiante ya matriculado en este período")
        
        // 4. Registrar inscripción
        nueva_inscripcion = InscripcionRepository.crear({
            estudiante_id: id_estudiante,
            seccion_id: id_seccion,
            anio_lectivo: anio_lectivo,
            fecha: HOY(),
            estado: 'activo'
        })
        
        CONFIRMAR Transaccion
        RETORNAR Exito(nueva_inscripcion)
        
    CATCH Exception e:
        REVERTIR Transaccion
        RETORNAR Error("Fallo en matrícula: " + e.mensaje)
FIN FUNCION
```

### 4.2 Algoritmo de Cálculo de Promedios (Optimizado con JOIN)

**Objetivo:** Calcular la nota final de un estudiante en una asignatura basada en las ponderaciones definidas, utilizando una única consulta SQL.

**Implementación en `CalificacionRepository`:**
```php
public function obtenerNotasPorSeccionYMateria(int $id_seccion, int $id_materia, array $evaluaciones): array {
    // Construir dinámicamente las columnas CASE para cada evaluación
    $caseColumns = '';
    foreach ($evaluaciones as $eval) {
        $caseColumns .= "MAX(CASE WHEN pe.id_plan = {$eval['id_plan']} THEN c.valor_obtenido END) AS nota_{$eval['id_plan']}, ";
    }
    $caseColumns .= "ROUND(AVG(c.valor_obtenido * pe.ponderacion / 100), 2) AS nota_final";

    $sql = "SELECT e.id_estudiante, e.nombres, e.apellidos, e.cedula_identidad,
                   $caseColumns
            FROM estudiantes e
            INNER JOIN inscripciones i ON e.id_estudiante = i.id_estudiante
            LEFT JOIN calificaciones c ON e.id_estudiante = c.id_estudiante
            LEFT JOIN planes_evaluacion pe ON c.id_plan = pe.id_plan
            WHERE i.id_seccion = :id_seccion AND pe.id_asignacion = (
                SELECT id_asignacion FROM asignaciones WHERE id_materia = :id_materia AND id_seccion = :id_seccion LIMIT 1
            )
            GROUP BY e.id_estudiante";

    $stmt = $this->db->prepare($sql);
    $stmt->execute([':id_seccion' => $id_seccion, ':id_materia' => $id_materia]);
    return $stmt->fetchAll(PDO::FETCH_ASSOC);
}
```

**Ventaja:** Una sola consulta reemplaza el bucle N+1, mejorando drásticamente el rendimiento.

### 4.3 Algoritmo de Control de Asistencia Masiva

**Objetivo:** Permitir al docente guardar la asistencia de toda la clase en una sola operación, con validación de fecha futura.

**Implementación en `AsistenciaService`:**
```php
public function registrarAsistenciaMasiva(array $asistencias, int $id_asignacion, string $fecha): array {
    $db = Database::getInstance()->conectar();
    $db->beginTransaction();
    
    try {
        // Validar fecha
        if (strtotime($fecha) > time()) {
            throw new Exception("No se puede registrar asistencia en fecha futura");
        }
        
        foreach ($asistencias as $item) {
            $sql = "INSERT INTO asistencias (id_estudiante, id_asignacion, fecha, estado, justificacion, registrado_por)
                    VALUES (:id_estudiante, :id_asignacion, :fecha, :estado, :justificacion, :registrado_por)
                    ON DUPLICATE KEY UPDATE
                        estado = VALUES(estado),
                        justificacion = VALUES(justificacion),
                        updated_at = CURRENT_TIMESTAMP";
            $stmt = $db->prepare($sql);
            $stmt->execute([
                ':id_estudiante' => $item['id_estudiante'],
                ':id_asignacion' => $id_asignacion,
                ':fecha' => $fecha,
                ':estado' => $item['estado'],
                ':justificacion' => $item['justificacion'] ?? null,
                ':registrado_por' => $_SESSION['usuario_id'] // Se obtiene de la sesión
            ]);
        }
        
        $db->commit();
        return ['success' => true, 'message' => 'Asistencia registrada correctamente'];
        
    } catch (Exception $e) {
        $db->rollBack();
        return ['success' => false, 'error' => $e->getMessage()];
    }
}
```

public function procesarLogin(): void {
    // Validar CSRF
    // Obtener IP
    $rateLimiter = new RateLimiter($this->db);
    if ($rateLimiter->isLimited($ip)) {
        $this->render('auth/login', ['error' => 'Demasiados intentos fallidos. Espere 15 minutos.']);
        return;
    }
    // Autenticar
    $usuario = UsuarioService::autenticar($login, $password);
    if ($usuario) {
        $rateLimiter->resetAttempts($ip);
        $_SESSION['usuario_id'] = $usuario['id_usuario'];
        $_SESSION['usuario_permisos'] = PermisoService::obtenerPermisosUsuario($usuario['id_usuario']);
        // Redirigir
        header('Location: index.php?url=admin/dashboard');
    } else {
        $rateLimiter->registerAttempt($ip);
        $this->render('auth/login', ['error' => 'Credenciales incorrectas']);
    }
}

**Flujo Principal:**
1. Usuario accede a la URL del sistema.
2. Sistema muestra formulario de login.
3. Usuario ingresa correo institucional o cédula.
4. Usuario ingresa contraseña.
5. Usuario envía formulario.
6. Sistema valida token CSRF.
7. Sistema verifica rate limiting (tabla `intentos_login`).
8. Sistema verifica credenciales en BD.
9. Sistema resetear intentos fallidos (si existían).
10. Sistema regenera ID de sesión.
11. Sistema carga todos los permisos del usuario desde `usuario_permisos` y los guarda en `$_SESSION`.
12. Sistema redirige al dashboard correspondiente.

**Flujos Alternativos:**
- 7a. Excede intentos: muestra mensaje de espera.
- 8a. Credenciales inválidas: registra intento fallido en `intentos_login` y muestra error.
- 8b. Cuenta inactiva: muestra mensaje de cuenta deshabilitada.

### 8.2 CU-015: Registrar Calificaciones

**Actor Principal:** Docente  
**Actores Secundarios:** Sistema  
**Precondiciones:**
- Docente debe tener permiso `calificaciones.registrar`.
- Debe tener asignaciones activas.

**Postcondiciones:** Calificaciones guardadas en base de datos, caché de dashboard actualizada.

**Flujo Principal:**
1. Docente navega a `profesor/calificaciones`.
2. Router verifica permiso `calificaciones.registrar`.
3. Sistema muestra lista de asignaciones del docente.
4. Docente selecciona materia y sección.
5. Sistema carga tabla de estudiantes con notas (usando consulta JOIN optimizada, una sola consulta).
6. Docente ingresa notas para cada estudiante.
7. Sistema valida rango de notas (0.00 - 20.00) en el lado del cliente y del servidor.
8. Docente envía formulario.
9. Sistema guarda calificaciones en BD (UPSERT).
10. Sistema actualiza la caché del dashboard del docente.
11. Sistema muestra Toast de confirmación (notificación flotante).

**Flujos Alternativos:**
- 7a. Nota inválida: el campo se marca en rojo, no se permite el envío.
- 9a. Error de BD: se muestra mensaje de error y se revierte la transacción.

### 8.3 CU-025: Solicitar Constancia

**Actor Principal:** Estudiante  
**Actores Secundarios:** Administrador (para aprobación)  
**Precondiciones:** Estudiante debe tener permiso `constancias.solicitar`.

**Postcondiciones:** Solicitud creada en estado `pendiente`.

**Flujo Principal:**
1. Estudiante navega a `estudiante/constancias/solicitar`.
2. Router verifica permiso `constancias.solicitar`.
3. Sistema verifica que el estudiante esté activo.
4. Sistema verifica que tenga menos de 3 solicitudes pendientes.
5. Estudiante selecciona tipo de constancia (estudio, conducta, notas).
6. Estudiante ingresa motivo (opcional).
7. Estudiante envía solicitud.
8. Sistema valida datos.
9. Sistema crea registro en `solicitudes_constancia` con estado `pendiente`.
10. Sistema muestra Toast de confirmación con número de solicitud.

**Flujos Alternativos:**
- 4a. Límite excedido: muestra mensaje y no permite nueva solicitud.
- 8a. Datos inválidos: muestra errores de validación.

## 11. SEGURIDAD Y VALIDACIONES

### 11.1 Medidas de Seguridad Implementadas

| Amenaza | Medida | Implementación |
|---------|--------|----------------|
| SQL Injection | Prepared Statements | PDO con parámetros nombrados |
| XSS | Sanitización + CSP | `htmlspecialchars()` + Content-Security-Policy header |
| CSRF | Tokens únicos | Token por sesión validado en POST |
| Session Fixation | Regeneración ID | `session_regenerate_id(true)` tras login |
| Brute Force | Rate Limiting | Tabla `intentos_login`, 5 intentos / 15 min |
| Clickjacking | X-Frame-Options | Header: SAMEORIGIN |
| MIME Sniffing | X-Content-Type-Options | Header: nosniff |
| Información sensible | Headers caché | Cache-Control: no-store |
| Contraseñas | Hash seguro | `password_hash()` con PASSWORD_DEFAULT |
| Acceso no autorizado | ACL en Router | Permisos asociados a rutas, verificados antes de ejecutar controlador |

### 11.2 Validaciones de Datos

- **Email:** Formato RFC válido, único por institución.
- **Fechas:** Formato `YYYY-MM-DD`. No se permiten fechas futuras para nacimientos o matrículas.
- **Calificaciones:** Numérico decimal, rango 0.00 - 20.00.
- **Ponderaciones:** Numérico decimal, suma total debe ser 100% por asignación.
- **Cédula:** Única, formato libre (para permitir diferentes países).
- **Archivos (logo):** Restricción a MIME types `image/jpeg, image/png` y max 2MB (futuro).

### 11.3 Auditoría

Todas las acciones que modifican datos (INSERT, UPDATE, DELETE) se registran en la tabla `auditoria` con:
- Usuario que realizó la acción.
- Acción (CREATE, UPDATE, DELETE, LOGIN, etc.).
- Tabla afectada y registro ID.
- Snapshot de cambios (JSON con old/new values).
- IP y User-Agent del cliente.

## 12. CRITERIOS DE ACEPTACIÓN TÉCNICA

| Criterio | Descripción | Métrica |
|----------|-------------|---------|
| **Rendimiento** | Consultas con JOIN (sin N+1) | Tiempo de carga < 1s para 100 estudiantes |

| **Interfaz responsive** | Uso de Bootstrap 5 y DataTables | Se visualiza correctamente en móvil y escritorio |
| **Seguridad** | Protección CSRF, XSS, SQL Injection | 0 vulnerabilidades en escaneo básico |
| **Integridad referencial** | Todas las claves foráneas están definidas | No se pueden eliminar registros con dependencias |

CREATE DATABASE IF NOT EXISTS sgcea_db
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;

USE sgcea_db;

-- Tabla: instituciones
CREATE TABLE instituciones (
    id_institucion INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(150) NOT NULL,
    codigo_centro VARCHAR(20) UNIQUE,
    direccion VARCHAR(255),
    telefono VARCHAR(20),
    email VARCHAR(100),
    logo_url VARCHAR(255),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- Tabla: usuarios (sin id_rol)
CREATE TABLE usuarios (
    id_usuario INT AUTO_INCREMENT PRIMARY KEY,
    correo_institucional VARCHAR(100) NOT NULL UNIQUE,
    cedula VARCHAR(20) UNIQUE,
    contrasena_hash VARCHAR(255) NOT NULL,
    estado_cuenta TINYINT(1) DEFAULT 1,
    primer_login BOOLEAN DEFAULT TRUE,
    ultimo_acceso TIMESTAMP NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_usuarios_correo (correo_institucional),
    INDEX idx_usuarios_cedula (cedula)
);

-- Tabla: permisos
CREATE TABLE permisos (
    id_permiso INT AUTO_INCREMENT PRIMARY KEY,
    nombre_permiso VARCHAR(50) UNIQUE NOT NULL,
    descripcion VARCHAR(255),
    modulo VARCHAR(50) DEFAULT 'general',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Tabla: usuario_permisos
CREATE TABLE usuario_permisos (
    id_usuario INT NOT NULL,
    id_permiso INT NOT NULL,
    PRIMARY KEY (id_usuario, id_permiso),
    FOREIGN KEY (id_usuario) REFERENCES usuarios(id_usuario) ON DELETE CASCADE,
    FOREIGN KEY (id_permiso) REFERENCES permisos(id_permiso) ON DELETE CASCADE
);

-- Tabla: profesores
CREATE TABLE profesores (
    id_profesor INT AUTO_INCREMENT PRIMARY KEY,
    id_usuario INT NOT NULL UNIQUE,
    nombres VARCHAR(100) NOT NULL,
    apellidos VARCHAR(100) NOT NULL,
    cedula_identidad VARCHAR(20) UNIQUE,
    especialidad VARCHAR(100),
    telefono VARCHAR(20),
    fecha_contratacion DATE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (id_usuario) REFERENCES usuarios(id_usuario) ON DELETE CASCADE
);

-- Tabla: estudiantes
CREATE TABLE estudiantes (
    id_estudiante INT AUTO_INCREMENT PRIMARY KEY,

    fecha_nacimiento DATE,
    genero ENUM('M', 'F', 'O'),
    direccion VARCHAR(255),
    telefono_padre VARCHAR(20),
    nombre_representante VARCHAR(100),
    telefono_representante VARCHAR(20),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (id_usuario) REFERENCES usuarios(id_usuario) ON DELETE CASCADE
);

-- Tabla: grados
CREATE TABLE grados (
    id_grado INT AUTO_INCREMENT PRIMARY KEY,

    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Tabla: secciones
CREATE TABLE secciones (
    id_seccion INT AUTO_INCREMENT PRIMARY KEY,
    grado_id INT NOT NULL,
    nombre VARCHAR(10) NOT NULL,

    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (grado_id) REFERENCES grados(id_grado) ON DELETE RESTRICT
);

-- Tabla: materias
CREATE TABLE materias (
    id_materia INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    codigo VARCHAR(20) UNIQUE,

    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
